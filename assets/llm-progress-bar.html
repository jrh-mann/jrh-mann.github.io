Making a Progress Bar for LLM Output

A priori, measuring how many more tokens an LLM will produce is not necessarily an easy task. The LLM might decide this early on, or update its estimate on the fly. In this project, we investigate how LLMs (Qwen3-4b) represent n_tokens_remaining, by analysing the residual stream.

We initially hypothesised that the model could represent this directly with a linear regression, or represent the log of this linearly, or do something outright different altogether. We investigated these hypotheses in turn. Producing a probe trained to predict n_tokens_remaning directly - lin_to_lin; a probe trained to predict log(n_tokens_remaining) - lin_to_log; and a probe trained to classify residuals into bins, where bin n covers all the residuals corresponding to between exp(n) and exp(n+1) tokens remaining - log_bin_classifier. All experiments are done on layer 15 of Qwen3-4B, a model with 36 layers.

Initial results suggested the "doing something different" hypothesis was the most promising - it produced a progress bar that looked the most reasonable out of the different hypotheses. Note, initially we disregarded the lin_to_log hypothesis due to worse R2 metric, we have since found that this was a result of a poor data mix, with too few samples at the extremes. We mitigate this using a balanced data mix, which aims to ~evenly include samples from across the n_tokens_remaining domain (elaborated later). Balancing: the initial naive data mix we tried threw in all tokens in the response. This massively over-representated the tokens from long rollouts i.e. was not uniformly distributed in log space. We resolved this by sampling 200 random sequence positions per rollout, this gave a metric to optimise over that was closer to the task at hand, giving equal optimisation power to sequences of different lengths.

We proceed using the balanced_lin_to_log estimator. Using which, we were able to graph how the predictions varied token-by-token in generation and use these to analyse how the model dynamically updates according to the most recently generated token, as well as expectations about upcoming tokens. Beginning with the latter, we find that predictions consistently drop precipitously in the ~50 tokens / sentence prior to the </think> token. We demonstrate this by comparing the typical drop in the tokens prior to </think>, with the baseline typical decrease during the rest of generation. On average, seeing a drop of 4 toks/token running up to </think> vs 0.8 as the baseline. This suggests the model is engaging in some level of planning, given it consistently updates its predictions downwards well in advance of that specific token. This also suggests the probe is working as expected as the model often knows in its concluding sentence to say </think> after.

We additionally provide some examples of the progress bar in the runup to </think>, demonstrating significant drops. The line corresponds to the predictions made by the model at each token, the first graph shown applies an EMA of 0.9 to the predictions for stability. Note the steady increase until ~60 tokens prior to </think>.

We can investigate this further however, by removing the EMA. This gives us a noisier graph but reveals that the actual effect of an imminent </think> is to bring far more consistency to the model's own predictions at consecutive timesteps.

We can now consider the former, how the model updates according to the most recently generated token. This is identified by taking an actual model response, pausing it after a full stop, then comparing the results of appending varying different tokens to the response and predicting the length on that new token. This has the effect of identifying which directions of thought correspond to bringing models closer to completing their response, and which push them away. We find strong evidence that it is certain tokens like "Definitely" and "Finally" that bring models closer, and uncertain tokens like "Wait", "Maybe", and "Alternatively" that push them away. This likely corresponds to the fact that uncertain tokens cause models to retry a problem in a different way. We take as baseline the probe's prediction on just the paused model response.

However, the effect is sensitive to the actual plausibility of the response + appendation. For example, in the above graph, the preceding line reads "...So I should assume it's in base 10, the standard system.\n\n". Appending any of the tested tokens to this is at least plausible and correct English. Taking instead, "...So I should assume it's in base" as the prefix causes the effect to reverse. This is because none of those appendations form correct English when placed after that prefix, "...So I should assume it's in base Bingo" being an atypical turn of phrase.

A more robust way to identify this effect, then, is to take the direction learnt by the probe, steer with it, and review which logits are boosted and suppressed. Doing so results in this set of tokens.

Some interesting things to note here are that several of the tokens boosted by positive steering (i.e. turning up length) are uncertain tokens, "perhaps" being the most significant of these. The other combinations are less interpretable. The suppression of <|endoftext|> by positive steering is perhaps expected, as the only token that guarantees response shortness being premature conclusion. Negative steering is less obviously interpretable, maybe formatting characters cause the model to move on and rattle through sentences more swiftly.

EMA-smoothing showed slight improvement on predictions, this is likely by counteracting the token-by-token noise seen in a previous graph. Note, we ignore the first 5 tokens as these were especially volatile, tending to be particularly low, this was especially harmful to EMA. With this in mind, we investigated the trajectories of responses. In the first case, by projecting the residual stream at each step in generation onto the learnt direction of the probe. This yields a set of curves visualised below. As token_idx increases, i.e. as the response gets closer to completion, the prediction decreases, this follows somewhat of an exponential, which is to be expected given the probe has been trained to predict log(n_remaining tokens).

We then return to the log_bin_classifier to see how the residual stream moves between phases. The following graph is found by taking the softmax of the classifier's predictions at each step of the generation. Then splitting these predictions up by bin, such that we can see the probability assigned by the probe to each bin at each step of generation. The part of the generation actually meant to correspond to the bin (for bin n the token_idxs between exp(n) and exp(n+1)) is coloured orange (or omitted if not on graph), and token_idx of </think> is given a green axis line. Notable from this graph is the transition between bins, this is characterised by a gradual increase prior to entering the orange section for each bin. This indicates we are learning some continuous bins that transition into each other. Also interesting is the effect of </think> on the bins, in the below example causing the model to very rapidly move from predicting bin 7 to bin 6.

We then investigate the actual trajectories in PCA space. We take as the basis of the PCA the mean of the residual streams within each of 19 bins. This performs well, the top 3 components explaining 87.65% of the variance of the mean bins. With this space established, we can investigate how responses move through it. Short Post-Mortem on Misleading Initial Results

In the initial analysis we did, we looked at the PCA of the weights of a logistic classifier predicting the floor(log(n_tokens_remaining)) i.e. a classification into the rough order of magnitude. We found later on that this method of analysing a representation is conceptually flawed, as shown by the following example:
